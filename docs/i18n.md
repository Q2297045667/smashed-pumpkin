# Internationalization infrastructure

## Scope

Phases 2–4 add GNU gettext, early language initialization, persisted preferences
and an application-language selector to the C/GTK/Meson application. The first
production Simplified Chinese catalog translates all currently marked GtkBuilder
and dynamic UI messages, covering navigation, settings, dialogs, server controls,
players, networks, plugins, worlds, minimap, statistics, About and feedback.
Backend diagnostics and the remaining release work still need separate auditing
and validation. Only installed application catalogs appear as selectable
languages; missing entries use source English.

The [phase 1 audit](<i18n-audit.md>) remains the reference for raw-data, protocol,
archive, and lifecycle boundaries. Its findings describe the pre-gettext state.

## Domain and build

- Domain: `smashed-pumpkin` (`GETTEXT_PACKAGE` in the generated configuration).
- Installed catalogs: `<prefix>/<localedir>/<language>/LC_MESSAGES/smashed-pumpkin.mo`.
- Both [Linux](<../resources/ui/window.ui>) and [Windows](<../resources/ui/window-windows.ui>)
  templates declare the same domain. Widget/action/page identifiers and option
  ordering do not change; application branding is not translated.
- [POTFILES](<../po/POTFILES>) lists real C and GtkBuilder sources. Never list
  generated resource C, configured metadata, or the Cambalache project as text sources.
- [The catalog scan](<../build-aux/list-translations.py>) automatically lists top-level
  `po/*.po` files at Meson configuration time. Adding a catalog requires no C, template
  or language-list edits. Reconfigure after adding/removing a file; edits to existing
  catalogs are tracked. [LINGUAS](<../po/LINGUAS>) stays empty for Meson's no-catalog
  compatibility path and must not contain a separate language list. English remains
  the source-language fallback; an English catalog is not needed.

GNU gettext tools (`xgettext`, `msgmerge`, `msgfmt`) are build dependencies. Meson
links the platform's `intl` dependency, which may be provided by libc on Linux.
The GLib extraction preset handles translation macros, format flags, and GtkBuilder
properties; `Translators:` comments are retained in the template.

```sh
meson setup build-i18n --wrap-mode=nodownload
meson compile -C build-i18n
meson compile -C build-i18n smashed-pumpkin-pot
# After adding/removing PO files (no LINGUAS or C changes):
meson setup --reconfigure build-i18n
meson compile -C build-i18n smashed-pumpkin-update-po
meson compile -C build-i18n smashed-pumpkin-gmo
```

Review generated template and PO changes before committing. Before releasing a
catalog, run `msgfmt --check --check-format` on its PO source. The test catalog
already uses both checks during compilation.

## Runtime initialization

Call `gtk_disable_setlocale()` followed by `pumpkin_i18n_startup()` exactly once,
before GTK/libadwaita initialization, templates or worker threads. The
[initializer](<../src/i18n.c>) prepares the saved preference, resolves the effective
language, sets `LANGUAGE`, applies the system locale and binds UTF-8 catalogs.
`LC_NUMERIC` is always restored to `C`: JSON, commands and decimal wire formats
retain `.`. The lower-level `pumpkin_i18n_init()` intentionally only initializes
gettext from the environment and is used by isolated gettext tests.

The Linux GTK 3 tray helper inherits `SMASHED_PUMPKIN_SESSION_LANGUAGE` from its
parent and keeps the current session's effective language, even after saving a
new preference. Standalone tray startup resolves the saved preference normally.
Windows main-program catalog lookup is source-level preparation only; Windows
runtime behavior and the untranslated Windows tray are not validated here.

`SMASHED_PUMPKIN_LOCALEDIR` is an optional **absolute** catalog directory for
uninstalled development builds and tests. Unset or relative values select the
configured `LOCALEDIR` when it contains a catalog for this domain; otherwise an
uninstalled build automatically falls back to the build-tree `po` directory,
so `./buildDir/src/smashed-pumpkin` discovers translations without installing.
Installed catalogs always win over the build tree; the fallback never changes
the language, only where catalogs are found. This override selects a catalog
location, not a language preference.

Missing catalogs or entries fall back to source English. Native Linux/glibc builds
bundle a tiny, messages-only `smashed.UTF-8` locale under
`<prefix>/<datadir>/smashed-pumpkin/locales`. Building it requires `localedef` and
the `en_US` locale source/UTF-8 charmap. No matching German or Chinese system locale
is required: if a non-English choice encounters C/POSIX, C-family or invalid system
locales, startup prepends that private root to `LOCPATH` and changes only
`LC_MESSAGES`. Character handling and date/time retain the system locale;
`LC_NUMERIC` remains `C`. `SMASHED_PUMPKIN_MESSAGE_LOCALEDIR` optionally selects
an **absolute** private-locale root for uninstalled builds. Relative values are ignored.
When the installed category is absent, uninstalled builds fall back to the mirrored
copy under the build tree (`buildDir/src/message-locales`).
The category is installed with the application, not generated during startup.

Flatpak builds must install app catalogs outside `/app/share/locale`: that
directory does not exist during module builds and flatpak-builder's finish
phase fills it with symlinks into the runtime locale tree, which would
replace the freshly installed app catalogs. The manifest therefore configures
`-Dlocaledir=share/smashed-pumpkin/translations`; catalog discovery and gettext
binding use the configured `LOCALEDIR`, so no code changes are needed. Verify
with `find /app/share/smashed-pumpkin/translations -name smashed-pumpkin.mo`
inside the built bundle.

Non-glibc platforms and cross builds do not generate that category; they attempt
`en_US.UTF-8` instead. Their C-only manual translation behavior is not verified.
Windows, Flatpak and release packaging acceptance remain separate work.

## Language preference and settings

[Language preparation](<../src/language.c>) reads `[behavior] language` in
`$XDG_CONFIG_HOME/smashed-pumpkin/config.ini`. The language selector starts with
`system` and source `en`, followed by sorted IDs discovered from valid
`<language>/LC_MESSAGES/smashed-pumpkin.mo` files in the active gettext root
(absolute environment override, installed catalogs, or the build-tree fallback).
The immutable list is scanned once per process before language initialization;
translated display names never become stored IDs. Without application catalogs,
only system and English are offered.

- On first startup, a missing or empty value is resolved to a concrete supported ID
  and atomically saved before creating widgets. Unrelated keys/comments are retained.
- A concrete saved choice overrides subsequent system changes and `LANGUAGE`.
- `system` detects on every startup without replacing the stored value.
- Detection mirrors gettext: `LC_ALL`, then `LC_MESSAGES`, then `LANG` provide
  the locale language; an explicit C/POSIX locale selects English. A nonempty
  colon-separated `LANGUAGE` list is tried first, entry by entry, with C/empty
  entries skipped and surrounding whitespace ignored; when no entry matches,
  the locale language is tried before falling back to English, so a failed
  `LANGUAGE` list never persists an English detection.
  Tags are normalized for case, encoding and hyphen/underscore variants; modifiers
  are tried before a less-specific fallback. Exact catalog IDs win, then optional
  aliases, then less-specific IDs (for example a region can use its base language).
  Different regions/scripts are never guessed as equivalent. Unsupported lists fall
  back to English. Windows also has a native locale fallback when the environment
  contains no preference.
- Unknown nonempty saved IDs use English without rewriting the value. Read/parse
  errors, including invalid string escapes, preserve the file and block ordinary
  configuration saves. Startup reports the error and safely continues in English.
  A first-run write failure reports the error but keeps the detected session language.
  Saving unrelated settings also preserves an unsupported raw ID when the language
  selector remains on its English fallback.

Configuration is a startup snapshot, not a live-editable file. External changes made
while the application is running are not merged; saves may replace those changes.
After externally repairing a load error, restart the application to reload the file.
Concurrent edits and hot reload remain separate work.

General settings → Display and time contains the language selector. Save persists
its stable ID and shows a next-launch notice; it never changes the current language,
automatically restarts the application or restarts running servers. Selecting the
original preference clears the notice after saving. Discard restores the saved
selection; Reset selects `system` but remains unsaved until Save. A failed save
keeps the pending choice and does not claim success. Date/time formatting is a
separate setting and does not follow the application language selection.

## Adding a language without code changes

Add a UTF-8 `po/<locale>.po`, for example `po/zh_TW.po` for a `zh_TW.UTF-8`
environment, then reconfigure, build and install. The next startup discovers its
compiled catalog automatically; system detection and the settings selector use the
same discovered IDs. A previous explicit selection remains respected: automatic
selection applies to first launch or the `system` preference, not an existing `en`.

The production Simplified Chinese catalog is [po/zh_CN.po](<../po/zh_CN.po>).
A PO header can optionally supply data for display names and equivalent locale
spellings, so those never require language-specific C branches:

```po
"Language: zh_TW\n"
"X-Language-Name: Chinese (Traditional)\n"
"X-Language-Aliases: zh_Hant;zh_HK;zh_MO\n"
```

Without these optional fields, the filename ID is displayed and an exact regional
match works. Aliases are semicolon-separated; a more specific environment can fall
back to an alias prefix such as `zh_Hant`. Declare cross-region equivalence only
when the catalog really supports it. Native display names may be used in released
catalogs. Test fixtures intentionally use English labels instead of real Chinese
translations. Malformed MO metadata and catalogs for other applications are ignored.
Copying an already compiled catalog into the installed gettext layout likewise
makes it available after restarting; this is not a live language-list reload.
Removing a PO file stops future builds after reconfiguration, but Meson does not
remove an older installed MO. Remove obsolete installed catalogs through packaging
or uninstall cleanup; discovery reflects the files actually present at startup.

## Adding messages safely

Include [i18n.h](<../src/i18n.h>) in C files that produce translatable presentation.

```c
const char *label = _("Stop");
const char *deferred = N_("Stop"); /* Translate with _(deferred) when displayed. */
const char *state = C_("connection-state", "Open");
const char *format = g_dngettext(GETTEXT_PACKAGE, "%u server", "%u servers", count);
char *summary = g_strdup_printf(format, count);
```

- Translate complete sentences; do not append English plural suffixes or assemble
  translated fragments into grammatical sentences.
- Preserve argument types and allow positional format arguments in translations.
  Add `Translators:` comments for opaque IDs, dates, placeholders, and ambiguous terms.
  Gettext extraction does not expand GLib integer-format macros: for translatable
  display text use complete literal formats such as `%llu` with an explicit
  `unsigned long long` cast, rather than `"%" G_GUINT64_FORMAT`. Leave protocol and
  persistence formats unchanged.
- Use a context for short words with different meanings. The GLib domain-specific
  plural helper avoids depending on another library's default gettext domain.
- Mark visible GtkBuilder properties/items `translatable="yes"`. Keep stable IDs,
  enum/index order, action and dialog response identifiers unmodified.
- Raw build metadata, JSON/INI keys, URLs, IDs, commands, raw server output, parser
  literals, and archived diagnostic syntax must stay unmodified. User and third-party
  content remains original; translate only application-provided explanations.
- Keep presentation separate from persistence. In particular,
  `pumpkin_build_metadata_format()` may translate Build/Stable/Nightly display text;
  its output must never become a persisted value or update/cache identity.

The Simplified Chinese catalog covers the current templates and marked application
UI messages: navigation, settings and validation, dialogs, installation/version
presentation, marketplace, players, networks, statistics, worlds, minimap, Feedback,
About, tooltips/accessibility labels, and Linux tray Open/Quit actions. Count summaries
use complete gettext plural messages; durations and relative times retain literal
format arguments. Existing manual German Feedback/About content is preserved.

Raw server output, archived notices, protocol match patterns and third-party content
are intentionally not translated. Backend error producers outside the extraction
list also retain their original diagnostics; translating those requires a separate
consumer/boundary audit or typed display mapping, not `_(error->message)`.

After changing the Linux template, update its SHA-256 reference in the
[Cambalache project](<../resources/smashed-pumpkin.cmb>). Check both template domains
and translation attributes after editor round trips; the Windows template is
compiled separately even though it is not registered by that project file.

## Verification

The small [German fixture](<../tests/i18n/de.po>) covers UTF-8 text, contextual
messages, plurals, dynamic formats and representative template properties. It is
compiled into the test build directory only and is **never installed or released**.
Native Linux tests use fresh processes for each locale environment because GLib
and gettext cache locale data. Ensure `en_US.UTF-8` exists for translated tests;
those tests report a skip if it is unavailable. CI generates that locale explicitly.

```sh
meson test -C build-i18n --print-errorlogs
bash build-aux/test-window-ui.sh build-i18n i18n-loading
bash build-aux/test-window-ui.sh build-i18n i18n-chinese
bash build-aux/test-window-ui.sh build-i18n i18n-boundaries
bash build-aux/test-window-ui.sh build-i18n language-settings
```

The translated GTK tests require a usable desktop display. The German fixture test
checks representative template and dynamic translations; the Simplified Chinese test
loads the production `po/zh_CN.po` catalog and checks catalog discovery, first-run
selection, template labels, dynamic navigation/build/stop presentation, zero/one/many
count forms, long-long duration formats, unchanged branding and raw build identity/update
decisions, and `LC_NUMERIC` after GTK initialization. It also runs the same raw-log,
poll-reply and typed lifecycle-event regressions as the English baseline, including
Chinese display-only notices containing protocol-like text. Both translated tests use
isolated configuration, a private bus/runtime directory, and a fake installed binary
without starting a server. The boundary regression retains an explicit English baseline.
The language-settings regression runs a fake local server and verifies stable-ID
persistence, reset/discard, write-error recovery and unchanged session language/server
state. It also verifies that both Save entry points persist date/time and card-display
preferences, and that saving general settings retains unrelated unsaved server drafts.
Cache recovery tests verify repeated misses do not create empty cache directories;
direct, cached and shared downloads still exercise the write path.
All UI tests use private profiles and do not touch existing servers. The UI harness
requires Python 3.9+ and Linux PID file descriptors for cleanup: it terminates only
helpers carrying the exact private profile in their environment, never the desktop's
own portal services, before removing the verified temporary directory.

The source test runs real extraction, checks both template domains and source-file
inputs, verifies complete integer-format and plural messages, and rejects representative
machine-data tokens from the catalog. Unit tests
cover English/missing-message/missing-catalog/invalid-locale/fallback behavior,
UTF-8, contexts, plural counts, raw metadata, and JSON/command numeric serialization.
Missing-catalog fallback runs with the same non-C locale as translated tests, so
C-locale suppression cannot accidentally satisfy the fallback assertion.

Language tests additionally protect unknown keys/comments, malformed files and
invalid language escapes, and force actual first-run write failure using a Unix
file-size limit (independent of root permissions). Synthetic catalogs verify arbitrary
new IDs, names, aliases, script boundaries, missing/corrupt files and modifier handling.
Fresh startup processes additionally cover Traditional Chinese first-run/system/manual
selection using an isolated fixture, private messages-only locales and source fallback.
The UI test discovers and saves the same new Traditional catalog without a template
language list. Private-locale scenarios only run on native Linux/glibc.
The configure-time scanner has independent tests for adding/removing PO files without
LINGUAS changes, sorted output and unsafe filenames.

## Remaining phases

- Audit backend error producers before translating their user-facing explanations;
  separate stable raw/archived diagnostics from display text where necessary.
- Migrate the preserved manual German Feedback/About branches into gettext without
  losing existing German content.
- Desktop/AppStream merging after placeholder substitution, preserving existing
  English/German release data and release-note validation.
- Windows tray UTF-16 drawing and sizing before adding gettext to that helper.
- Native-install/Flatpak packaging, catalog paths, font/locale behavior and platform
  acceptance. The current tests validate the local Linux native build only.
